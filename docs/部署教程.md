# 安装与部署教程

**使用宝塔且已装好 Nginx／PHP／MySQL：优先按[宝塔面板部署教程](宝塔面板部署教程.md)操作，不必重复安装服务。**

本教程对应随包程序：原生 HTML 前端、PHP API、SQLite／MySQL，无 Composer、npm 或外部 CDN 运行依赖。真正的 Excel 由程序生成 OOXML，依赖 PHP 的 ZipArchive 与 XMLWriter。

**验收范围：本轮已完成隔离 SQLite 与本地 HTTP／浏览器验证，未执行原生 PHP CLI、Argon2id 成功登录、MySQL、Nginx/PHP-FPM/HTTPS 或系统 cron 部署。以下命令是目标环境操作说明，不是已经运行成功的记录。年级版结果详见[全年级升级说明](全年级升级说明.md)。**

Windows 本地步骤用于体验和验收；全班正式使用采用 HTTPS、Nginx、PHP-FPM 与 MySQL。实际班级名单、管理员身份和服务器地址由你自行配置，示例学号及域名必须替换。

## 1. 环境要求与目录

使用部署时官方支持且已修补的 PHP。当前源码预设生产版本门槛为 PHP 8.5.12 或 PHP 8.4.27 起，但本轮未能连接官方站点重新核实公告、包修订及 SHA-256；该门槛不等于官方安全证明。先完成官方复核再安装，详见[安全与 PHP 运行时说明](安全与PHP公告.md)。

要求扩展：PDO、PDO SQLite（本地）、PDO MySQL（正式）、OpenSSL、mbstring、ZipArchive、XMLWriter；密码哈希支持 Argon2id。程序会做环境检查。

| 目录 | 用途 | 是否公开 |
| --- | --- | --- |
| `public/` | HTML、CSS、JS、API 入口 | 网站根目录 |
| `src/` | 业务与安全代码 | 否 |
| `bin/` | 命令行初始化及维护 | 否 |
| `config/` | 配置示例及本地配置 | 否 |
| `storage/` | 数据库、会话、临时文件等运行数据 | 否 |
| `docs/`、`templates/`、`deploy/` | 手册、模板及服务器配置示例 | 不需要作为网站公开 |

**网站根目录只指向 `public/`。不能把整个解压目录设成网站根目录。**

## 2. Windows 本地体验

### 2.1 安装并校验 PHP

从 [PHP 官方 Windows 下载清单](https://downloads.php.net/~windows/releases/releases.json) 取得当前已修补的 x64 包名及对应 SHA-256，再下载同名包。本轮没有完成官方下载校验，不使用旧稿摘要。下载后在 PowerShell 执行（替换为实际文件名）：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\从官方下载的实际文件名.zip'
```

结果须与官方同名包一致，再解压，例如放在 `C:\Tools\php`。若启动提示缺少 VC 运行库，按 PHP Windows 官方要求安装微软对应的 x64 Visual C++ Runtime，不从未知网站下载 DLL。[PHP Windows 下载页](https://windows.php.net/download/)

将 `php.ini-development` 复制为 `php.ini`，检查或启用：

```ini
extension_dir = "ext"
extension=openssl
extension=mbstring
extension=pdo_sqlite
extension=sqlite3
extension=pdo_mysql
extension=zip
session.upload_progress.enabled=0
session.serialize_handler=php
date.timezone=Asia/Shanghai
```

XMLWriter 可能已内置；先用 `php -m` 检查，不要盲目添加不存在的扩展 DLL。不要同时重复启用同一扩展。

### 2.2 在项目目录初始化

解压源码后，在 `dorm-check` 目录打开 PowerShell。以下假定 PHP 放在 `C:\Tools\php`：

```powershell
$env:Path = 'C:\Tools\php;' + $env:Path
php -v
php --ini
php -m
php bin/console.php init --env=development --url=http://127.0.0.1:8765 --db=sqlite --class=电科一班
php bin/console.php doctor
```

初始化创建 `config/local.php` 和 `storage/` 下的 SQLite 数据库，自动生成密钥。不要把本地配置或运行数据发到群里、上传公开仓库。已初始化时不要为“重试”删除数据库；先查看错误并按升级或恢复流程处理。

`doctor` 的失败项必须处理；开发环境的 HTTP 地址仅允许受控本地使用，不等于已经满足正式 HTTPS 部署条件。

### 2.3 建立管理员或使用虚构演示数据

使用你核实后的真实学号建立首名管理员，下面的 `00100000`、`示例班长` 只是示例：

```powershell
php bin/console.php user:create --student-no=00100000 --name=示例班长 --role=admin
```

命令输出一次性激活码，妥善单独交给对应本人。没有固定默认密码。

如仅需查看虚构示例，**在创建任何账号之前**，可在空的 development 数据库运行下述命令；与上面的手动创建首名管理员方式二选一：

```powershell
php bin/console.php demo
```

演示命令输出虚构账号和一次性激活信息；不要将演示数据库转成正式班级数据库。正式环境不能运行演示命令。

### 2.4 启动并打开页面

```powershell
php -S 127.0.0.1:8765 -t public public/router.php
```

保持终端运行，在浏览器打开 `http://127.0.0.1:8765/`。先进入“首次激活”设置密码，再登录；管理员按引导绑定验证器。具体操作见[使用手册](使用手册.md)。

`127.0.0.1` 只供本机访问；关闭终端或电脑后服务停止。不要把 PHP 内置服务器绑定公网作为正式服务。[PHP 官方说明](https://www.php.net/manual/en/features.commandline.webserver.php)

### 2.5 本地自动任务

手动执行一次检查：

```powershell
php bin/console.php tick
```

若要持续体验，可在 Windows“任务计划程序”建立每分钟重复任务：程序为完整 `php.exe` 路径，参数为项目 `bin\console.php` 的完整路径加 `tick`，起始目录设为项目目录，选择正确 Windows 账号。此任务不能替代正式服务器的长期运行。

## 3. Linux 正式部署

下面以提供 PHP 8.5 软件包的 Debian／Ubuntu 系服务器、Nginx 和 MySQL 为命令示例。软件源、包名及候选安全版本须以目标发行版实际结果为准，本轮未对该 Linux 环境实机部署；不要仅凭发行版名称推定已具备所需 PHP。

### 3.1 服务器和域名准备

准备具有 sudo 权限的维护账号，将域名 A／AAAA 记录指向服务器，只开放必需的 SSH、80 和 443 端口。保留可用 SSH 管理通道后再调整防火墙，数据库及 FPM 端口不对公网开放。

本文使用 `/var/www/dorm-check` 和 `dorm.example.com`；按实际路径和你持有的域名替换。不要直接使用示例域名申请证书。

### 3.2 安装服务并核对安全版本

```bash
sudo apt update
sudo apt install nginx mysql-server php8.5-cli php8.5-fpm php8.5-mysql php8.5-sqlite3 php8.5-xml php8.5-zip php8.5-mbstring unzip certbot
apt-cache policy php8.5-cli php8.5-fpm
php8.5 -v
php8.5 --ini
php8.5 -m
```

若仓库候选仍低于本项目安全基准，先从受信任并持续维护的软件源取得已修补 PHP，或让服务器供应商完成升级，再继续。不要把“安装成功”当成安全版本已满足，也不要改掉程序的版本检查来绕过。供应商回补版本须有明确修补证据；本次交付按上游修补版验证，不自动认可任意旧版号的回补包。

确认 MySQL 和 PHP-FPM 服务正常：

```bash
sudo systemctl enable --now mysql php8.5-fpm nginx
sudo systemctl status mysql php8.5-fpm nginx
```

### 3.3 放置源码与权限

由维护账号上传、解压源码到 `/var/www/dorm-check`。不要覆盖已有正式 `config` 或 `storage`；首次部署与升级分别处理。

首次部署时，在确认目标路径正确后设置权限：

```bash
sudo chown -R root:www-data /var/www/dorm-check
sudo find /var/www/dorm-check -type d -exec chmod 750 {} \;
sudo find /var/www/dorm-check -type f -exec chmod 640 {} \;
sudo install -d -o www-data -g www-data -m 750 /var/www/dorm-check/storage
sudo install -d -o root -g www-data -m 750 /etc/dorm-check
sudo install -d -o www-data -g www-data -m 750 /var/log/dorm-check
sudo install -d -o root -g root -m 700 /var/backups/dorm-check
```

现有 `storage/` 中的运行文件需保持 `www-data` 可读写；源码不应允许 Web 账号写入。不要使用 `chmod 777`。

### 3.4 创建数据库

通过交互式 MySQL 管理会话建立专用数据库及账号：

```bash
sudo env MYSQL_HISTFILE=/dev/null mysql
```

在 MySQL 提示符中执行，密码替换为你单独生成的强密码：

```sql
CREATE DATABASE dorm_check CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'dorm_app'@'127.0.0.1' IDENTIFIED BY '替换为独立强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX ON dorm_check.* TO 'dorm_app'@'127.0.0.1';
EXIT;
```

初始化和迁移需要建表权限；正常运行后可撤销 CREATE、ALTER、INDEX，升级需要迁移时再受控授予。不要使用 MySQL root 作为网站运行账号。

### 3.5 设置私有环境配置

建立 `/etc/dorm-check/runtime.env`，由 root 维护、组为 www-data、权限 640。内容示例：

```sh
DORM_CONFIG=/etc/dorm-check/config.php
DORM_DB_DSN='mysql:host=127.0.0.1;port=3306;dbname=dorm_check;charset=utf8mb4'
DORM_DB_USER=dorm_app
DORM_DB_PASSWORD='与数据库账号一致的独立强密码'
```

该文件会由 shell 和 systemd 环境文件读取，按示例保留正确引号；不要填换行值。密码不要写在命令行参数、公开配置或聊天消息中。

```bash
sudo chown root:www-data /etc/dorm-check/runtime.env
sudo chmod 640 /etc/dorm-check/runtime.env
sudo -s
set -a
. /etc/dorm-check/runtime.env
set +a
cd /var/www/dorm-check
php8.5 bin/console.php init --env=production --url=https://dorm.example.com --db=mysql --class=电科一班
chown root:www-data /etc/dorm-check/config.php
chmod 640 /etc/dorm-check/config.php
php8.5 bin/console.php doctor
php8.5 bin/console.php user:create --student-no=你的真实学号 --name=班长姓名 --role=admin
exit
```

中文示例值需替换，不能用示例管理员身份正式上线。激活码仅在操作时单独记录；不要把整个维护终端输出作为公开部署日志。

### 3.6 将环境变量传给 PHP-FPM

CLI 的环境不会自动传给 FPM。建立 systemd 覆盖：

```ini
# /etc/systemd/system/php8.5-fpm.service.d/dorm-check.conf
[Service]
EnvironmentFile=/etc/dorm-check/runtime.env
```

在实际 FPM 池配置中加入环境白名单；使用默认池时文件通常为 `/etc/php/8.5/fpm/pool.d/www.conf`：

```ini
env[DORM_CONFIG] = /etc/dorm-check/config.php
env[DORM_DB_DSN] = $DORM_DB_DSN
env[DORM_DB_USER] = $DORM_DB_USER
env[DORM_DB_PASSWORD] = $DORM_DB_PASSWORD
```

保持 FPM 只监听本机 Unix socket。不要为方便直接向 Web 进程传入所有环境变量；备份密钥不会加入 FPM 白名单。

### 3.7 应用 PHP 安全配置

```bash
sudo cp /var/www/dorm-check/deploy/php-production.ini /etc/php/8.5/fpm/conf.d/99-dorm-check.ini
sudo cp /var/www/dorm-check/deploy/php-production.ini /etc/php/8.5/cli/conf.d/99-dorm-check.ini
sudo systemctl daemon-reload
sudo php-fpm8.5 -t
sudo systemctl restart php8.5-fpm
```

必须在启动配置中关闭 `session.upload_progress.enabled` 并重启全部 worker。CLI 与 FPM 配置分别核实；不能只看 `php --ini` 就认定 FPM 一样，也不能只在业务代码里调用 `ini_set()`。

### 3.8 获取证书并启用 Nginx

先创建 ACME 目录：

```bash
sudo install -d -o root -g www-data -m 755 /var/www/acme
```

将 `deploy/nginx-http.conf.example` 复制到 Nginx 站点配置，替换域名，建立对应 `sites-enabled` 链接后检查并重载。这个临时配置只开放证书挑战，不开放应用：

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo certbot certonly --webroot -w /var/www/acme -d dorm.example.com --email 你的邮箱 --agree-tos
```

证书取得后，用 `deploy/nginx.conf.example` 替换临时配置，修改域名、源码路径、证书路径及实际 FPM socket。然后执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo certbot renew --dry-run
```

证书续期须由系统已有的 certbot timer 或你配置的任务执行；检查 `systemctl list-timers`。确认 HTTPS 和续期都正常后再启用示例中的 HSTS。

浏览器访问正式 HTTPS 地址，激活管理员、按当前策略绑定二次验证，并建立班级、导入已核实名单和分配班委的班级权限。宿舍负责人使用免登录入口，不创建宿舍长角色账号。外置配置中的 `app_url` 必须与实际访问的协议、主机及端口一致，否则来源校验可能拒绝请求。已有单班系统先看[全年级升级说明](全年级升级说明.md)。

### 3.9 撤销运行账号的建表权限

初始化成功并完成首轮检查后，在 MySQL 管理会话执行：

```sql
REVOKE CREATE, ALTER, INDEX ON dorm_check.* FROM 'dorm_app'@'127.0.0.1';
```

升级如确需迁移，临时恢复所需权限，迁移结束再撤销。普通页面不能修改数据库结构。

## 4. 每分钟计划任务

创建 `/etc/cron.d/dorm-check`，由 root 持有、权限 644，使用实际 PHP 路径：

```cron
* * * * * www-data /bin/sh -c 'set -a; . /etc/dorm-check/runtime.env; set +a; exec /usr/bin/php8.5 /var/www/dorm-check/bin/console.php tick' >> /var/log/dorm-check/tick.log 2>&1
```

先用同一身份手动执行一次，并确认返回结果和后台运行信息。日志文件只允许必要账号访问，配置系统日志轮转，不能无限增长。

定时任务运行在服务器，即使无人打开网页也会执行。服务器需校准时间；业务使用 Asia/Shanghai。漏跑后的补跑应保留真实执行时间，不能把后来数据伪装成原时点已经掌握。

## 5. 备份与恢复

### 5.1 建立独立备份密钥

备份使用 AES-256-GCM，`DORM_BACKUP_KEY` 是 32 字节随机值的 base64。保存在独立的 root 私有文件 `/etc/dorm-check/backup.env`，不要放进 FPM 环境。可在受控 root 终端生成：

```bash
sudo -s
umask 077
if [ -e /etc/dorm-check/backup.env ] || [ -L /etc/dorm-check/backup.env ]; then
    echo '备份密钥文件已存在；请保管原文件，不要覆盖。'
else
    if key="$(openssl rand -base64 32)" && [ -n "$key" ] && (set -C; printf 'DORM_BACKUP_KEY=%s\n' "$key" > /etc/dorm-check/backup.env); then
        echo '已创建新的私有备份密钥文件。'
    else
        echo '密钥生成或写入失败；请检查后再继续。' >&2
    fi
    unset key
fi
exit
```

将密钥另行离线保管；仅有 `.dcb` 文件但丢失密钥无法恢复。备份密钥不随公开源码包提供。

### 5.2 手动备份

```bash
sudo -s
set -a
. /etc/dorm-check/runtime.env
. /etc/dorm-check/backup.env
set +a
php8.5 /var/www/dorm-check/bin/console.php backup --output=/var/backups/dorm-check/首次验收.dcb
exit
```

MySQL 备份依赖 `mysqldump`，恢复依赖 `mysql`；确认与服务器版本兼容且位于 PATH。凭据通过程序生成的受限临时选项文件传递，不出现在命令行参数。SQLite 使用一致性快照。

备份为自定义 v2 `.dcb` 格式，按 1 MiB 分块进行 AES-256-GCM 认证，带终止块，拒绝篡改和尾随数据；文件及展开数据上限为 512 MiB。归档包含数据库、清单及选定应用配置（含应用加密密钥，不含数据库密码），不是整个网站目录的备份。恢复不会自动覆盖 `config/local.php` 或外置配置，请另行安全保存数据库连接配置和部署文件，并在恢复后按返回提示人工核对配置。

MySQL 恢复会执行 dump 中的建表及 `DROP TABLE` 等语句。普通 Web 账号不常驻 DROP 权限；应在维护窗口使用受控维护账号，或仅为 CLI 恢复进程临时设置所需 DDL、DROP 和数据写入权限，结束即撤销。先在隔离库核实该 MySQL／mysqldump 版本实际需要的权限（例如表锁、触发器），不要直接给网站账号全局权限。该路径本轮未实机验证。

每天备份可由独立 root cron 加载上述两个环境文件后执行同一命令，使用唯一输出文件名。cron 中 `date` 格式里的 `%` 要写为 `\%`。建议保留 30 天并另行保存重要归档；先验证恢复再按规则清理，避免只剩一份不可用备份。

### 5.3 恢复演练与故障恢复

首先保存现状备份并确认目标数据库、备份文件和密钥。恢复会替换业务数据，只在受控维护时执行：

```bash
sudo -s
set -a
. /etc/dorm-check/runtime.env
. /etc/dorm-check/backup.env
set +a
php8.5 /var/www/dorm-check/bin/console.php maintenance:on
php8.5 /var/www/dorm-check/bin/console.php restore --input=/var/backups/dorm-check/首次验收.dcb --confirm=RESTORE
```

恢复成功会把非停用账号置为待恢复、清除旧密码及 TOTP，并撤销旧会话、激活码、重置码、恢复码和全部旧授权。根据当前可信名单重新核对账号，逐个为核实人员发放新重置码。若恢复中途失败而留下全阻断维护标记，先修复并重新完成恢复，不得直接解除维护：

```bash
php8.5 /var/www/dorm-check/bin/console.php user:reset --student-no=已核实的管理员学号
```

维护模式允许登录、重置密码及重新绑定二次验证等身份恢复操作，业务读写保持暂停。管理员完成重置和二次验证绑定，再恢复其他必要人员。对离任账号执行 `user:disable`，不沿用备份中的旧授权直接开放。

核对名册、任务、报表、到期数据以及可能缺失的时段，至少恢复一名有效且已绑定二次验证的管理员后，执行：

```bash
php8.5 /var/www/dorm-check/bin/console.php doctor
php8.5 /var/www/dorm-check/bin/console.php maintenance:off --confirm=REVIEWED
exit
```

记录恢复点、操作人和已知数据缺口。不要在正式库上为了“试一下”随意覆盖，首次演练应使用隔离的测试数据库和测试地址。

## 6. 账号维护命令

下列命令均在正确项目和配置环境下运行；生产环境先加载 `runtime.env`：

```bash
php bin/console.php user:create --student-no=真实学号 --name=真实姓名 --role=committee
php bin/console.php user:reset --student-no=真实学号
php bin/console.php user:disable --student-no=真实学号
php bin/console.php mfa:reset --student-no=已核实的管理人员学号
```

创建和重置返回一次性凭据；单独交付本人，勿公开截图。`mfa:reset` 属服务器受控恢复，核实本人后才执行，之后重新绑定验证器。管理员在后台分配班委的班级权限；宿舍负责人在名单中维护，无需登录账号。

## 7. 数据保留与本地回归

设置页的 `retention_days` 是建议保留天数，不会自动执行删除。维护人员先核对政策、保存可恢复备份，再明确指定截止日期；命令只清理该日期之前的记录，截止日期必须早于今天：

```bash
php bin/console.php prune --before=2026-01-01 --confirm=PRUNE
```

示例日期必须替换，勿直接复制到正式库。清理会影响旧晚任务、事件、固定日报及到期运行信息；程序同时限制调度游标，避免下次补跑重建已清理的旧晚。

在具备原生 PHP 的隔离环境中进行回归：

```bash
php tests/run.php
php tests/grade.php
node --check public/assets/app.js
node tests/http.mjs http://127.0.0.1:8765
```

PHP 测试直接使用内存 SQLite 和独立临时目录，不读取运行配置或真实名单；测试会明确列出缺少 Argon2id 时的跳过项。HTTP 测试只验证匿名边界，另开隔离开发实例后运行，不对正式服务做验收操作。Node 仅用于测试，不是生产运行依赖。年级版隔离验收结果见[全年级升级说明](全年级升级说明.md)，不能代替目标 PHP、MySQL 和 HTTPS 的现场验收。

## 9. 升级与故障排查

升级前进入维护模式、保存可恢复备份、记录当前 PHP 和程序版本。先在测试环境验证新版本，再更新源码；保留受控配置和运行数据，不用新包覆盖旧数据库。需要迁移时按该版本说明临时授予所需数据库权限，完成后重新撤销。重启 FPM，运行环境检查和关键业务回归，确认后解除维护。

| 现象 | 优先检查 |
| --- | --- |
| 502 Bad Gateway | FPM 是否运行，Nginx socket 路径及权限是否正确 |
| API 提示未初始化 | `DORM_CONFIG` 与配置文件权限，CLI 与 FPM 环境是否一致 |
| 数据库连接失败 | FPM 环境白名单、DSN、账号主机、MySQL 服务和权限 |
| PHP 安全配置不通过 | 实际 FPM 版本、扫描目录、上传进度配置，是否重启全部 worker |
| 请求来源不正确 | `app_url` 是否与实际 HTTPS 地址一致，代理是否正确传递 HTTPS |
| 登录后立即退出 | Cookie／HTTPS、服务器时间、账号状态及会话目录权限 |
| 任务不自动生成 | cron 身份、环境文件、PHP 路径、日志和服务器时间 |
| Excel 导出失败 | zip、xmlwriter、临时目录、近期验证状态及当前权限 |
| CSV 乱码或前导零丢失 | UTF-8 编码、Excel 单元格文本格式及原始 CSV |
| 动态码总不正确 | 手机和服务器时间同步、账号对应的验证器条目 |

查看 Nginx、FPM 和应用日志时仅向维护人员提供必要的错误编号和去敏内容。不要把数据库密码、配置密钥、激活码或整班信息贴进公开问题反馈。
