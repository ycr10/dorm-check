# 08:00 日期切换与单日筛选：升级说明

本轮仅修改本地代码，未连接真实服务器、未改动真实数据。

## 一、日期规则

便捷登记、已登录后台默认日期，以及任务、总览、跟进、抽查和日报接口的默认查询日期统一按北京时间：

- **00:00:00–07:59:59**：前一晚；
- **08:00:00 起**：当天。

例如 10 月 31 日 07:59:59 默认查 10 月 30 日，08:00:00 默认查 10 月 31 日。服务器时间是准则；设备时间不能提前开放登记。以前一晚不存在时，不自动伪造历史任务。如果当天任务缺失，08:00 起打开默认业务页面或便捷入口可按既有逻辑补建；已有名单无需每天重新上传。

管理员和班委仍可通过日期选择器查看自己有权访问的任意历史日期；手动选择后固定该日期，点击“恢复默认”可重新跟随服务器业务日期。未结项旧任务仍保留，但必须选择其所属日期后查看和补报。日报固定版本、历史事件和冻结名册不因本次升级而重写。

日期选择器及 `tasks` 接口现在**严格只返回所选日期**，不会附带之前所有未结项任务。为兼容旧客户端，返回结构中的 `open_tasks` 保留为空数组；使用过此字段的其他客户端需要调整。总览、跟进、抽查和日报也按所选日期查询。计划任务 `tick` 仍按自然日运行及补跑，浏览器日期切换不能替代自动调度。

上传后强制刷新页面，用隔离实例和虚构名单检查：07:59:59／08:00:00 边界、任意历史日期、今日及无任务日期；确认只显示所选日期的数据，管理端授权和历史日报仍正常。

## 三、API 404 显示 Nginx HTML

浏览器收到 Nginx HTML 404 不等于能够确定 API 文件不存在：应用本身找不到当晚寝室时也会返回 HTTP 404 JSON；Nginx 或上游代理可能把它替换成 HTML 页面。你反馈不存在的 API 动作也显示 HTML，表明需检查实际站点规则，但不能仅凭此认定拦截发生在哪一层。

以现场域名访问 `/api/index.php?action=unknown_action`，应用正常应返回 HTTP 404 JSON、代码 `NOT_FOUND`；JSON 中的 `csrf` 不要公开。若仍是 HTML，检查站点当前 API 对应 location、`fastcgi_intercept_errors` 和 `error_page`，以及反向代理／防护规则。本项目示例和宝塔教程在**现有的 API FastCGI location 内**显式设置：

```nginx
fastcgi_intercept_errors off;
```

这是示例，不要新建重复的 `location`，也不要重复声明同一指令；如果同一 location 中已有 `fastcgi_intercept_errors on;`，应结合实际配置替换其值。仅在确认 API 实际由该 FastCGI location 处理后修改。修改前备份站点配置并检查完整配置，`nginx -t` 通过后，由维护人员在合适时段决定是否平滑重载。Nginx 可能由多个网站共享，即使只修改本站 location，重载也是共享服务操作；不修改全局 PHP，也不擅自重启服务。如果 `off` 后仍返回 HTML，还需检查上游代理或 WAF，不能保证本条必然解决。

即使 JSON 404 能正常展示，缺失任务、名单和负责人的情况仍会报告 `QUICK_NOT_FOUND`；日期切换不会凭空创造不存在的前一晚。先检查名单和当晚任务，而不是反复导入或清库。
