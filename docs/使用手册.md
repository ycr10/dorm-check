# 归寝 · 全年级使用手册

本系统用于记录和跟进晚间返寝情况，不作为成绩考核。系统管理员管理年级、班级和管理账号；班委只可查看和管理获授权班级的学生。宿舍负责人不需要登录账号。

## 一、日常日期与时间

- 默认查寝时点为北京时间 22:30，初报截止 22:35；系统管理员可调整全年级规则。
- 00:00:00–07:59:59 默认查看前一晚，08:00:00 起默认查看当天。服务器时间为准，修改手机时间不能提前开放登记。
- 后台日期选择器**只显示所选日期**。手动选定后日期固定；点击“恢复默认”重新跟随服务器业务日期。更早的未结项记录仍保留，需选择其所属日期查看。
- 每日名册按当时住宿关系准备并在查寝时点冻结。现有名单不需要每天重新导入；计划任务负责无人打开网页时的调度和自动日报。

## 二、宿舍负责人便捷登记

1. 从登录页进入“寝室长便捷登记”，或打开站点的 `/quick.html`。
2. 输入当前负责人学号和房间号；房间号只填房间编号并保留前导零。未找到唯一任务时，请联系管理员核实名单、宿舍和负责人关系。
3. 核对当晚宿舍、日期和每位成员。跨班混住的同学会在**同一个宿舍表单**中显示。
4. 如全员确实在寝，可点击“一键全到”填充可编辑人员的状态；仍须逐人检查、勾选确认并提交。未归或待核实人员填写必要的已知情况。
5. 保存成功后可逐人补报当前状态；原始初报保留。迟报且现在的情况已变化时，分别填写查寝时状态和当前状态。

**此入口不验证填报人身份。** 知道负责人学号和房号的人可能冒充登记或查看同寝最低限度的信息；操作记录标记“便捷入口（未验证身份）”，不能证明实际填报人。班级后台权限不会消除这一风险。系统不要求在共用设备上保存学号或房间号；自愿勾选时，浏览器 Cookie 最多保存 30 天，可随时清除，不保存名单、密码或申报内容。

负责人变更由管理员在“名单与授权 → 班级与账号 → 交接负责人”核实处理。新负责人必须在该宿舍的有效名单中；快捷登记按**当前**负责人关系核验，已冻结的历史快照不改写。

## 三、管理账号和两步验证

1. 管理员核实本人后建立班委或管理员账号，并单独发放一次性激活码。没有公开注册或通用初始密码；不要使用学校统一认证密码。
2. 班委账号必须由管理员分配一个或多个班级；没有班级授权时无法查看学生业务数据。管理员可管理全年级，也可切换到单班查看。
3. 管理员在“名单与授权 → 班级与账号”设置班委班级范围。权限变化会使目标账号的现有会话失效，需要重新登录；撤权后旧会话及旧提交重试不能继续访问被撤销范围。
4. 若原宿舍长之后需要班委账号，管理员须重新核实本人并明确创建管理角色、发放新激活码和分配班级；旧账号不自动获得新权限。

管理员可在“系统设置 → 两步验证账号”指定一个已激活且未停用的学号。尚未指定时，管理员和班委按原管理账号策略绑定验证器；指定后只有该学号需要并允许绑定。更换指定账号会按提示撤销其他绑定和所有旧会话。绑定密钥、动态码与恢复码只供本人使用，不发到群里。

## 四、班级名单与负责人

1. 管理员先建立班级，再由管理员或获授权班委选择该班导入名单。使用[空白模板](../templates/名单导入模板.csv)，以 Excel 将学号和房间号设为文本后另存 UTF-8 CSV；不能直接导入 XLSX。
2. 列为“班级、学号、姓名、楼栋、房间号、寝室长学号”。班级列留空时使用所选目标班级；填写时必须与目标班级一致。其他字段必填，每份文件最多 2 MB、1,000 人。
3. 文件先预览，再确认。重复学号、目标班级不匹配或宿舍负责人冲突必须处理；预览后内容、班级或相关名单发生变化时须重新预览。导入不自动创建账号，也不会删除本次文件中未出现的学生。
4. 同一楼栋与房间号表示同一物理宿舍，各班导入的负责人学号必须一致。负责人暂未导入或不在该宿舍时会提示，核实补齐前该寝无法便捷登记；跨班负责人交接由管理员统一处理。
5. 学生转班须由对来源和目标班级均有权限的人核实；历史查寝归属保留。移出当前名册需填写原因，不自动删除历史或停用管理账号。仍被其他人引用为宿舍负责人的，先完成交接。

## 五、后台查寝、跟进与日报

- 顶部“班级范围”可选择全年级／全部获授权班级或单个班级。无权班级的数据不因修改前端或猜测编号而可访问。
- “我的查寝”显示所选日期与范围内的宿舍成员。混住宿舍中班委只对自己获授权的成员初报、补报和更正，不代填其他班；整寝是否完成要等所有应报成员完成。
- 草稿只属于当前账号，不计初报。名册或报告版本变化时重新读取并核实，不用旧表单覆盖新结果。
- 结项、重新开放和调整当晚完整名册会影响整个宿舍，必须对该寝涉及的所有班级有权限，或由系统管理员操作；需要填写原因，原始记录和固定日报保留。
- “异常跟进”分别处理未归、待核实和缺报。“已确认安全”是联系结果，不自动等于“已在寝”。请假／特殊住宿只登记已核实安排，不替代学校正式审批。
- “历史日报”可查看最新情况或固定版本，复制汇报文字或经近期验证导出六表 Excel。班级范围的人数和进度仅统计授权学生；混住宿舍按包含该班成员的物理寝室计数。文件下载后需自行妥善保管。

| 状态 | 含义 |
| --- | --- |
| 已在寝 | 已核实人在宿舍 |
| 外出未归 | 已知未在寝，仍应返寝 |
| 已核实无需返寝 | 存在有效且已核实的安排 |
| 待核实 | 尚不能确认人员情况 |
| 未登记 | 系统尚无有效申报，不能当作已归 |

## 六、系统设置与常见问题

- **备案信息：**管理员在“系统设置 → 网站备案信息”填写 ICP 与公安备案号，默认留空；登录页、后台及便捷页从本站设置读取。运营者应自行核对备案及查询链接。
- **计划任务：**页面刷新不代替服务器 `tick`。长时间没有成功运行记录时联系维护人员，检查本站计划任务和服务器时间。
- **提示版本冲突：**重新读取最新任务、逐人核实后重新提交，不反复用旧表单覆盖。
- **看不到某班或学生：**先核对当前班级范围、管理员授予的权限和名单。不要借用他人账号，也不要把正式名单发到公开渠道。
- **升级、备份和恢复：**已有单班系统必须先备份并按[全年级升级说明](全年级升级说明.md)预检迁移。恢复新版备份后旧密码、会话、一次性码、TOTP 和班级授权会被撤销；须在维护模式中核实并重建。旧版备份不能直接覆盖新版数据库。
