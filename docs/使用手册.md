# 归寝 · 使用手册

本系统用于班级晚间返寝情况登记。学号识别账号，个人密码验证本人；寝室长、代理人和班委分别使用自己的账号，不共享密码。

默认查寝时点为每天北京时间 22:30，建议初报截止为 22:35。实际开放时间以页面和班委配置为准。系统用于确认安全，与考核成绩无关。

## 一、首次登录

### 普通寝室长与代理人

1. 向班委核实本人学号和负责宿舍。
2. 从管理员处单独领取一次性激活码。
3. 打开系统地址，切换到“首次激活”。
4. 输入学号和激活码，设置个人密码，完成激活。
5. 切换“学号登录”，输入自己的学号和密码。

激活码过期、输错或已使用时，联系管理员核实后重新发放。只知道学号不能自行认领账号。不要输入学校统一身份认证密码；请为本系统设置独立密码。

### 班长、团支书和系统管理员

**两步验证按系统设置的学号决定，不再固定按职务决定。** 在管理员尚未配置“系统设置 → 两步验证账号”之前，兼容原规则：班委、管理员仍须绑定。配置后，只有指定学号需要并允许绑定，其他班长、班委和寝室长用学号＋密码登录。

被要求绑定的账号，按引导打开“我的账号 → 二次验证 → 绑定验证器”。将页面显示的密钥手动添加到验证器应用，输入生成的六位动态码完成验证。妥善保存页面显示的恢复码，不发到群里。

未完成当前账号要求的二次验证时，先完成账户设置，再进入业务页面。更换手机前先确认恢复方式。遗失验证器时使用恢复码；恢复码也遗失时由服务器维护人员按受控恢复流程处理。

### 仅保留一个账号的两步验证

由系统管理员进入“系统设置 → 两步验证账号”，填写本人完整登录学号，点击“保存两步验证账号”并确认。必须选已激活且未停用的账号，保留前导零，不能留空。敏感操作可能要求重新输入密码和当前验证器动态码。

保存变更会保留指定账号原有的绑定和恢复码，解除其他账号的绑定并作废其恢复码，同时让所有账号重新登录。指定账号若尚未绑定，重新登录后须完成绑定。以后其他账号的“我的账号”显示“未指定此账号”，没有绑定入口；角色及寝室授权不变。

仅保存其他日常设置，或再次保存同一学号，不会重复撤销绑定和会话。详细升级、上传清单及验证边界见[指定账号两步验证升级说明](指定账号两步验证升级说明.md)。

### 网站备案信息

管理员进入“系统设置 → 网站备案信息”，填写完整 ICP 备案号与公安备案号并保存；公安备案号需包含“公网安备”、数字及“号”。保存可能要求重新验证身份。两项默认留空，清空后即不显示；设置保存在本站数据库，不写入公开源码。登录页、管理后台和免登录便捷页读取配置并显示，公安图标为本地文件。请核实各页面及备案平台生成的查询链接与备案主体；未填写或接口不可用时不会显示。

## 二、寝室长每天如何登记

### 免登录便捷登记

从登录页选择“寝室长便捷登记”，或访问站点的 `/quick.html`。输入寝室长学号和寝室号（只填房间号，保持前导零），无需创建登录账号；系统以当前有效名单里的寝室负责人和房号匹配当晚寝室。若没有唯一匹配，请联系班委核对负责人和房号。

进入后先逐人核实，选择“一键全到”可一次填好可编辑人员的“已在寝”；仍需核对并勾选确认后提交。有人外出、待核实或有核实的无需返寝安排时，应逐人修改。已初报后在同页逐人补报最新状态；原始初报保留。迟报时如情况已变化，展开人员下方“迟报时情况已变化？填写当前状态”，分别填写查寝时和现在的情况，避免把后来返寝误当作查寝时已经在寝。

当天 00:00—07:59:59 显示前一晚，08:00 起显示当天任务；已结项、暂停或尚未开放的任务不能提交。旧晚需要更正、代理或交接时使用原有登录流程并联系班委。

自愿勾选“在这台设备的浏览器记住学号和寝室号”后，本机 Cookie 最多保存 30 天；不保存成员名单、密码或登记状态。可使用“清除已记住的信息”，共用设备不要勾选。

**学号和寝室号不是身份凭据。** 任何知道这些信息的人都可能冒充寝室长查看本寝当晚最少人员信息、提交或修改登记；记录会标记“便捷入口（未验证身份）”，不能证明实际填报人。仅在已理解并接受该风险的场景使用，仍需班委核对信息。入口不提供管理后台、全班名单和任意历史查询。

### 已登录的原有登记方式

1. 打开“我的查寝”，核对查寝日期、楼栋和房间。
2. 在正式开放后进入今晚任务，核对系统列出的成员。
3. 按实际核实情况逐人选择状态，补充必要的去向说明。
4. 检查整寝汇总和未填项，再确认提交。
5. 等待系统显示保存成功及接收时间。失败或断网提示意味着尚未完成提交。

可以主动批量确认已经核实在寝的人员，但不能未经核实直接全选。初报不会自动复制昨天的状态。

已保存的班级名单会用于后续每天的任务，不需要每天重新上传。08:00 起打开默认日期的查寝页面会尝试补建当天任务；08:00 前默认读取前一晚，缺失的历史任务不会被伪造。计划任务仍负责无人打开网页时的调度和自动日报。若仍看不到，请先核对日期、名单、授权与计划任务状态，不要反复导入。名册不对时请联系班委，不要用其他同学的行代填；整寝报告校验不通过时，修改提示的问题后重试。

### 在线草稿与迟报

开放前可以“保存在线草稿”，草稿只属于当前账号和该寝室任务，不算正式初报。正式提交前必须重新核实并勾选确认。名册版本变化时旧草稿不会自动套用；已初报后草稿清除。退出账号后不会把草稿显示给下一位使用者，但可以重新登录本人账号读取尚有效的服务端草稿。

迟报时，表格左侧填写**查寝时点**的状态及去向，右侧填写**当前变化**及当前去向。例如，查寝时在图书馆、现在已经返寝，初报选择“外出未归／图书馆”，当前选择“已在寝”，不要继续把图书馆填成当前去向。当前仍外出但换了地点，应明确填写新的当前去向；当前为“外出未归”或“待核实”时，当前去向／已知情况必填。

“与查寝时点一致”表示沿用初报状态及去向；人工变化时间不确定时留空，系统仍保存真实接收时间。转入成员已有初报时，该表保留原值，后续变化走补报或更正。

## 三、如何选择人员状态

| 状态 | 应在什么情况下选择 |
| --- | --- |
| 已在寝 | 确认本人已经在寝室 |
| 外出未归 | 确认未在寝，知道大致去向且当晚仍应返寝 |
| 已核实请假／无需返寝 | 存在已核实的有效请假或特殊住宿安排 |
| 待核实 | 无法确认其去向或是否在寝 |
| 未登记 | 系统显示尚无有效申报，不能当作已归 |

去向写确认安全所需的简述，例如“图书馆”“回家”“校外活动”，不要求写详细病情、精确地址或无关隐私。

仅听说“已请假”，尚未核实许可时，按当前已知事实登记并注明待确认，请班委核实；不要直接当作已批准不返寝。

“确认安全”是联系结果，“已在寝”是人员状态，两者分别记录。

## 四、人员回来后如何补报

1. 在“我的查寝”选择对应晚间任务。
2. 打开返寝补报，选中已经核实回来的人员。
3. 若知道具体返寝时间，填写人工申报时间；不知道则以确认已在寝的时间记录。
4. 确认后提交，等待保存结果。

补报只需要更新发生变化的人，不用重填整张表。系统保留配置的查寝时点初报，另外记录后来的变化。“查看本晚记录”可查看原始初报、更正值、当前状态和完整时间线，展开事件可看原值与新值。

午夜后仍选择原晚任务。例如，10 月 30 日 00:20 回来，应在“10 月 29 日晚”的任务中补报。未处理完的任务不会因零点自动消失。

如果首次填表已经迟报，并且有人在查寝时点之后回来，要分别填写查寝时点情况和当前情况，不能用现在的状态代替原来时点。例如默认规则下应分别填写 22:30 时与当前的情况。

“我的查寝”只列出所选日期、当前获授权的任务；更早未结项任务请使用日期选择器切换到其原日期。后台总览、跟进和日报也只显示所选日期。手动选定后日期会固定；点“恢复默认”可重新跟随服务器业务日期。旧晚任务交给新负责人时，班委必须明确指定完整任务编号，不能只修改当前寝室长关系。班委在所有成员均已核实、没有缺报或待处理状态时可结项；重新开放必须填写原因，旧记录保留。

## 五、原来填错了怎么办

使用更正入口，说明原记录哪里错误以及核实后的情况。更正与后来返寝的补报属于不同操作。

系统会保留原值、更正值、操作人、理由和时间。需要班委处理的历史或已结项记录，联系班委处理，不通过反复提交覆盖原报告。

如果系统提示“数据已变化”或“版本冲突”，重新加载最新记录再核对提交；不要持续重复点击。

## 六、班长和团支书的每日工作

### 1. 查看今日总览

在“今日总览”查看人数分类、宿舍已报和未报情况，并核对“数据截至时间”。自动刷新会有短暂间隔，必要时手动刷新。

### 2. 处理异常

打开“异常跟进”，分别检查：

- 已确认应返寝但尚未回来的人员。
- 去向或在寝情况待核实的人员。
- 宿舍未报、人员未登记。

记录跟进人、联系情况及结果。已联系或确认安全不会自动把人员设成已在寝；确认回寝后仍需要人员状态更新。

### 3. 登记抽查

记录对象、时间、发现情况和核实结果。发现与申报不同先核实，再通过有理由的更正处理，不自动判定瞒报。

### 4. 查看日报并汇报

打开“历史日报”，选择日期以及固定版本或最新快照，核对缺报与待核实范围后导出 Excel，或生成汇报文字复制给辅导员。

首版不会自动发送到微信或 QQ 群；网页关闭后的外部推送也需要另行接入。

总览和系统设置显示计划任务最近运行结果。超过三分钟没有成功记录时联系维护人员检查；页面自动刷新不代替服务器计划任务。漏跑后补生成的日报明确显示实际生成时间和延迟，不声称是原截止时点已知的数据。固定版本的人员明细和时间线来自同一份快照，选择旧版本不会混入后来事件。

## 七、名单、账号和授权管理

“名单与授权”用于维护学生名单、账号与授权、请假安排。

### 名单导入

先使用随包的 `templates/名单导入模板.csv` 整理数据，保存为 UTF-8 编码，学号和房间号保持文本格式。当前版本导入 CSV，不直接导入 XLSX；如原表为 Excel，先将学号和房间号设置为文本，再另存为“CSV UTF-8”。

列为“班级、学号、姓名、楼栋、房间号、寝室长学号”；班级可留空使用系统配置，其余必填。寝室长学号必须能在本次导入或已有学生名册中找到。支持 UTF-8 BOM，最大 2 MB、1,000 行。

导入先预览，检查重复学号、缺少宿舍、负责人未匹配等问题，确认后再正式保存。同一份 CSV 在预览和确认间发生变化时，须重新预览。导入仅建立名单和住宿关系，不自动创建登录账号；管理员还需为负责人建立账号并发放激活码。

正式名单不会随程序包提供。演示数据均为虚构，正式部署应使用另外初始化的空数据库，不要把演示数据库当作正式库。

CSV 是新增／更新，不是整班替换：本次没出现某人，不会自动删除该同学。需要转班、离班或停止纳入后续名册时，在“学生名单”使用“移出当前名册”，填写核实原因。仍是其他学生寝室负责人的，先完成交接。移出不会删除已冻结的旧晚记录，**也不会自动停用本人账号或撤销授权**，需分别核实处理。重新纳入可再次导入核实后的 CSV。

### 授权与代理

寝室长只获得明确指定的寝室及任务范围。临时代报设置开始和结束时间，使用代理人本人的学号账号。负责人交接及时撤销旧授权；如有旧晚未结项任务，需要明确交接。

修改学生当前宿舍不会静默改掉过去日报。冻结后的当晚范围调整须记录理由，保存名册版本。

### 调整已冻结的当晚名册

班委在“我的查寝”打开“调整当晚名册”，核对完整勾选范围、填写理由后保存。该操作只改本晚，不改日常住宿关系。跨寝转移先在原寝移除，再在目标寝加入；原始事件和固定日报保留。目标寝不能覆盖转入人员已有的原始初报；初报后补列的人员由班委带理由补正。成员全部移出的空范围会自动结项，不再计为应报或缺报寝室。

提交时如果名册或报告版本已变，重新读取最新任务再核实，不继续套用旧表单。

### 请假与特殊住宿

登记已有许可的有效日期、确认来源和必要说明。本系统的登记不替代学校正式请假流程。许可过期或撤销后及时复核，不能长期沿用旧安排。

## 八、Excel 如何阅读

| 工作表 | 用途 |
| --- | --- |
| 当日汇总 | 人数分类、宿舍进度、统计口径及版本 |
| 全员明细 | 每位同学的初报、最新情况、去向和时间 |
| 应归未归 | 确认应返寝但尚未返寝的人员 |
| 缺报与待核实 | 未提交、未登记及情况不明的不同类型 |
| 请假与无需返寝 | 当晚已核实安排 |
| 补报与更正记录 | 变化前后、操作者、理由和时间 |

所有工作表对应同一份数据快照。补报之后重新导出产生新的截至时间或版本，原来已下载的文件不会自动更新。

只有具备导出权限者可以下载。文件下载后不再受网站撤权控制，应按班级要求妥善保管和到期清理。

## 九、账号与常见问题

| 问题 | 处理方法 |
| --- | --- |
| 登录提示学号或密码不正确 | 核对学号前导零和密码；仍失败时联系管理员，不连续猜测 |
| 账号尚未激活 | 使用管理员单独发放的有效激活码 |
| 动态码错误 | 核对手机时间自动同步及验证器中对应条目，等待下一组码重试 |
| 登录后看不到某个寝室 | 当前账号可能未获该范围授权，请班委核对，不共用别人账号 |
| 填报入口尚未开放 | 以服务器时间和系统配置为准，修改手机时间无效 |
| 保存失败或断网 | 视为未提交，保留页面并恢复网络后核对重试 |
| 长时间无操作退出 | 闲置会话会过期，重新登录；后台自动刷新不会无限续期 |
| 已汇报后又有人回寝 | 补报后查看最新快照，必要时重新导出并说明截至时间 |
| 显示应归人员到齐但有人请假 | 表示所有应返寝人员在寝，获准不返寝者另外列出 |
| 网站无法访问 | 班委联系维护人员检查服务、证书、数据库和运行日志 |

在共用设备上使用完毕主动退出，不只关闭标签页；不向他人透露密码、激活码、动态码和恢复码。
