# 宝塔面板部署教程（Nginx + PHP + MySQL 已安装）

适用项目：**归寝 · 班级晚查寝系统**，Linux 宝塔面板，独立域名或子域名。

本文从“宝塔已经装好 Nginx、PHP、MySQL”开始，不重复安装这些服务。项目不需要 Node、Composer、npm、Redis，也不需要创建 Node 项目或启动 `php -S`。生产入口是 **Nginx → PHP-FPM → MySQL**。

> **验收边界：**本项目已有隔离 SQLite、HTTP 和浏览器测试结果，但本轮没有在实际宝塔、原生 PHP／MySQL 上部署。以下是按当前源码编写的操作步骤，不是已经通过的服务器验收记录。首次部署先只建管理员，完成激活、登录、MFA、导出、定时任务等现场验收后，再导入正式名单。

## 一、先确定这几个值

全文使用以下示例，操作前统一替换；不要把示例域名直接当成自己的域名。

| 项目 | 本文示例 | 你需要填写的内容 |
| --- | --- | --- |
| 访问域名 | `dorm.example.com` | 已解析到服务器的独立域名／子域名 |
| HTTPS 地址 | `https://dorm.example.com` | 最终访问地址，不带子路径 |
| 项目目录 | `/www/wwwroot/dorm.example.com` | 宝塔网站目录 |
| 网站运行目录 | `/www/wwwroot/dorm.example.com/public` | 项目目录下的 `public` |
| PHP 命令 | `/www/server/php/85/bin/php` | 网站实际选用版本的 CLI 完整路径 |
| PHP-FPM socket | `/tmp/php-cgi-85.sock` | 该版本实际监听地址 |
| 数据库名 | `dorm_check` | 新建的专用空库 |
| 数据库用户名 | `dorm_app` | 仅访问该库的专用账号 |
| 班级名称 | `你的班级名称` | 实际班级名称 |

路径中的 `85` 只是宝塔 PHP 8.5 的常见目录名，**不代表具体补丁版本**。若使用 PHP 8.4，常见路径是 `/www/server/php/84/bin/php`，socket 也要相应核对，不能只替换命令而不替换网站 PHP 版本。

本教程的终端命令使用 Linux Bash，不是本地 Windows PowerShell。应在宝塔终端或 SSH 中执行。涉及权限的命令假定当前是 root；宝塔计划任务中则按下文降为网站运行用户执行。

## 二、检查现有 PHP 是否满足程序要求

### 2.1 核对版本及扩展

宝塔：**软件商店 → 已安装 → 对应 PHP → 设置**。页面名称可能随面板版本略有不同。

当前源码的生产版本门槛为：

- PHP 8.4：至少 `8.4.27`；
- PHP 8.5 及后续 PHP 8.x：至少满足源码 `Security::versionSafe()` 的判断，例如 PHP 8.5 至少 `8.5.12`。

这是**源码预设门槛**，不是本教程对最新 PHP 安全公告的重新核验。部署时仍需确认所用版本处于官方支持期并已修补。仅安装了“PHP 8.5”并不足以判断满足要求，不要修改版本检查来绕过。

在服务器终端执行：

```bash
/www/server/php/85/bin/php -v
/www/server/php/85/bin/php --ini
/www/server/php/85/bin/php -m
/www/server/php/85/bin/php -r 'echo "Argon2id: ", in_array("argon2id", password_algos(), true) ? "OK" : "MISSING", PHP_EOL;'
```

正式 MySQL 部署要求：

- `PDO`、`pdo_mysql`
- `openssl`
- `mbstring`
- `zip`（提供 `ZipArchive`）
- `xmlwriter`（提供 `XMLWriter`）
- 原生 `Argon2id` 密码哈希支持

部分扩展已经内置，不一定会出现在宝塔“安装扩展”列表中，以实际检查结果为准。**Argon2id 显示 `MISSING` 时应先解决 PHP 构建／版本问题，不能改成较弱算法来部署。**

`pdo_sqlite` 不是正式 MySQL 网站的必需扩展；如要在服务器运行项目自带的隔离 SQLite 回归测试，则需要另行具备它。

### 2.2 多站点默认方案：不修改共享 php.ini

**本教程默认服务器还运行着其他网站。不要到“软件商店 → PHP → 配置文件”里修改该版本的全局 `php.ini`，也不要直接覆盖共享 FPM 池配置。** 使用同一 PHP 实例的其他网站可能依赖不同的 Session、上传限制、错误显示、内存限制及禁用函数设置。

本项目改用以下作用域：

| 设置 | 本教程采用的位置 | 作用范围 |
| --- | --- | --- |
| Web 请求的上传进度、Session 序列化和错误显示等 | 第七节，本项目 Nginx 的精确 API location 内的 `PHP_ADMIN_VALUE` | 该入口的 PHP 请求，不写共享 `php.ini` |
| CLI 环境检查所需设置 | PHP 命令的 `-d` 参数 | 当前命令进程，不写配置文件 |
| 数据库密码 | 本项目 `config/db-password.php` | 本项目 |
| Cookie、会话私有目录和业务时区 | 本项目启动代码 | 本项目请求 |
| 防跨站读取范围 | 本项目 API location／站点配置 | 本项目，不能扩大到其他站点 |

必须在会话及请求处理前生效的 `session.upload_progress.enabled=0`，由 FPM 接收固定的 `PHP_ADMIN_VALUE` 参数设置；不是在业务代码中事后调用 `ini_set()`。`session.serialize_handler=php` 同样在入口配置，而不是运行中切换。

第七节的 Nginx 片段已包含这些配置，**不要另外把 `deploy/php-production.ini` 复制到宝塔全局配置目录**。该文件只是其他受控部署方式的参考，不是多站点共享 PHP 的必做步骤。应用自行设置生产 Cookie 属性及 Asia/Shanghai 业务时区，无需因此改整台服务器的时区或其他网站的 Cookie。

CLI 使用这种形式：

```bash
/www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php -r 'echo "upload_progress=", ini_get("session.upload_progress.enabled"), PHP_EOL;'
```

下面初始化、检查、账号及计划任务命令均带这两个 `-d` 参数。它们只影响本次 PHP 进程；普通的 `php -v`、`php -m` 不需要它们。

**边界：**站点参数不能替代安装缺失扩展，也不能把旧 PHP 变成新 PHP。如果现有共享 PHP 缺少必要能力，不要为了本项目直接升级所有网站或修改共享扩展／禁用函数列表。应使用只供本项目使用的合适 PHP 实例或容器；仅需要分开管理 worker 和池参数时，可由维护人员建立独立 FPM 池。独立池仍可能共用 PHP 二进制和扩展，不等于独立运行时。

保存本项目 Nginx 配置后先 `nginx -t`，通过后才做平滑 reload，不需要为这些站点参数重启共享 PHP。实际 API 请求仍须验证，CLI 成功不能证明 FPM 一定配置正确。如果目标 FPM 不接受入口参数，或与现有池的管理级限制冲突，应停在本项目排查或改用受控独立池，不要退回到修改所有网站的全局配置。

如果你已按旧版教程改了共享 PHP：先根据修改前备份核对并仅撤回本次改动，不要用另一份示例文件覆盖整个 `php.ini`。共享 PHP 的重载／重启仍会涉及同实例其他网站，需要安排维护窗口并验证其他站点。

## 三、建立网站并上传正确的目录

### 3.1 在宝塔添加 PHP 网站

进入 **网站 → PHP 项目／添加站点**：

1. 域名填写你的域名，例如 `dorm.example.com`。
2. 网站目录填写 `/www/wwwroot/dorm.example.com`。
3. PHP 版本选择上面已检查通过的版本。
4. 不需要 FTP；数据库可以按下一节单独创建。
5. 建站后先停止该站点，避免在运行目录尚未配置时公开上传的整个项目。

如果该域名已经在运行其他网站，不要直接覆盖其目录或配置；给本项目使用独立站点和独立空库。

### 3.2 上传应用本身

从本地上传 **`outputs/dorm-check/` 里面的内容**到站点目录，不是上传整个工作区。最终结构应为：

```text
/www/wwwroot/dorm.example.com/
├── bin/
│   └── console.php
├── config/
│   └── example.php
├── deploy/
├── docs/
├── public/
│   ├── index.html
│   ├── assets/
│   └── api/
│       └── index.php
├── src/
├── storage/
├── templates/
├── tests/
└── README.md
```

注意：

- 不要多套一层变成 `/www/wwwroot/dorm.example.com/dorm-check/public`，除非后面所有路径也随之更改。
- 不上传 `work/php-wasm/`、虚构预认证会话文件或本地浏览器 profile。
- 如打包上传，将压缩包放在 Web 根目录外解压；不要在可公开访问的目录遗留源码压缩包、SQL、备份或配置副本。
- 这是首次部署流程。已有运行数据时不得用新包覆盖 `config/local.php`、私有密码文件和 `storage/`。

### 3.3 设置运行目录

进入 **网站 → 该站点 → 设置 → 网站目录**：

- 网站目录：`/www/wwwroot/dorm.example.com`
- **运行目录：`/public`**
- 默认文档保留 `index.html`。

最终 Nginx 的 `root` 必须是：

```nginx
root /www/wwwroot/dorm.example.com/public;
index index.html;
```

**不要把项目根目录直接作为公开根目录。** `config/`、`src/`、`storage/`、`bin/` 等全部应在公开根目录之外。

## 四、在宝塔创建专用 MySQL 数据库

进入 **数据库 → MySQL → 添加数据库**：

- 数据库名：`dorm_check`
- 用户名：`dorm_app`
- 密码：单独生成的强密码，保存在密码管理器中
- 字符集：`utf8mb4`，例如 `utf8mb4_unicode_ci`
- 访问权限：限制本机；本文采用 TCP `127.0.0.1`，请为这个来源建立匹配的账号授权，可使用面板的“指定 IP：127.0.0.1”选项

不要使用 MySQL root 作为网站账号，不要选择允许所有 IP，不需要在安全组开放 3306。MySQL 应仅通过本机连接供应用访问。

本文连接参数固定为：

```text
mysql:host=127.0.0.1;port=3306;dbname=dorm_check;charset=utf8mb4
```

如果 MySQL 实际端口不是 3306，或使用其他库名，后面的 DSN 也必须修改。`'dorm_app'@'localhost'` 和 `'dorm_app'@'127.0.0.1'` 不是可以无条件互换的账号配置；若报拒绝连接，核对实际来源和授权，不要改成远程通配权限来解决。

**目标库必须是专用空库。** 不需要导入现成 SQL，程序初始化会建表；也不要将其他系统的库拿来试。初始化和迁移需要建表相关权限，日常运行权限的收紧见第十一节。

## 五、设置项目权限和私有数据库密码

### 5.1 先确认 PHP-FPM 运行用户

宝塔常见运行用户为 `www`，但必须以该版本 FPM 池实际配置中的 `user`、`group` 为准。若不是 `www`，全文对应用户名和组名都要替换。不要修改别的网站的运行用户来适配本教程。

在 root 终端先确认路径和账号：

```bash
ls -ld /www/wwwroot/dorm.example.com
ls -ld /www/wwwroot/dorm.example.com/public
id www
command -v runuser
```

路径不是本项目、账号不匹配或命令不存在时先处理，不要继续照抄权限命令。若系统没有 `runuser`，可由维护人员使用等效的、明确以 FPM 用户执行的 `su`／`sudo -u` 方式，不能把计划任务长期改成 root 来绕过权限问题。

首次部署、确认目录内只有本项目后，执行：

```bash
APP=/www/wwwroot/dorm.example.com

find "$APP" -type d -exec chown root:www {} +
find "$APP" -type d -exec chmod 750 {} +
find "$APP" -type f ! -name '.user.ini' -exec chown root:www {} +
find "$APP" -type f ! -name '.user.ini' -exec chmod 640 {} +

chown -R www:www "$APP/storage"
find "$APP/storage" -type d -exec chmod 700 {} +
find "$APP/storage" -type f -exec chmod 600 {} +
```

效果：源码、配置由维护人员管理，网站用户可以读取但不能修改；只有 `storage/` 允许网站用户写入。这里特意不修改宝塔可能加锁的 `.user.ini`，不要为了一次递归修改去全局取消防护。**不要用 `chmod 777`。**

上述命令按普通文件和目录处理，不应使用符号链接拼接站点目录。若 Nginx worker 与 FPM 不是同一用户／组，还需按实际账号给予它读取 `public/` 的必要权限。

### 5.2 创建私有密码文件

使用宝塔文件编辑器在下列位置新建文件：

```text
/www/wwwroot/dorm.example.com/config/db-password.php
```

内容：

```php
<?php
declare(strict_types=1);

return '这里替换成数据库用户 dorm_app 的真实密码';
```

保存为 UTF-8，不加 `?>`。若密码包含单引号或反斜杠，在 PHP 单引号字符串中分别写成 `\'`、`\\`；这里不是要求改变实际数据库密码。

然后设置权限并检查语法：

```bash
chown root:www /www/wwwroot/dorm.example.com/config/db-password.php
chmod 640 /www/wwwroot/dorm.example.com/config/db-password.php
/www/server/php/85/bin/php -l /www/wwwroot/dorm.example.com/config/db-password.php
```

只有语法检查通过再继续。该文件位于 `public/` 外，包含明文数据库凭据，只能供受控服务器进程读取。不要截图公开，也不要用“通过网址打开它”的方式检查内容。

采用此方式是为了避免宝塔里常见的“终端能连库，网页却没有环境变量”的问题；无需向共享 FPM 池全局写入数据库密码。

## 六、初始化正式配置和数据库

### 6.1 从私有文件临时加载初始化环境

在同一个 root Bash 终端依次执行，替换域名、库名、用户名及班级名称：

```bash
export DORM_DB_DSN='mysql:host=127.0.0.1;port=3306;dbname=dorm_check;charset=utf8mb4'
export DORM_DB_USER='dorm_app'

DORM_DB_PASSWORD="$(/www/server/php/85/bin/php -r 'echo require "/www/wwwroot/dorm.example.com/config/db-password.php";')"
export DORM_DB_PASSWORD
```

第三条命令失败时先修正错误，不要继续。不要执行 `echo "$DORM_DB_PASSWORD"`，也不要把密码写成命令行参数。确认当前终端没有从其他项目继承 `DORM_CONFIG`，本教程使用默认配置位置：

```bash
unset DORM_CONFIG

/www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php /www/wwwroot/dorm.example.com/bin/console.php init \
  --env=production \
  --url=https://dorm.example.com \
  --db=mysql \
  --class='你的班级名称'
```

成功会输出 `"ok":true`，并生成：

- `config/local.php`：环境、网站地址、应用随机密钥等配置；
- MySQL 表结构及初始设置；
- 当日任务的初始准备数据。

**不要手工复制 `example.php` 代替初始化。** `init` 会检查环境、生成随机应用密钥并安装数据库。没有默认管理员，也没有默认密码。

若提示配置已存在或数据库非空，先核查当前状态，不要删除数据库或反复强行初始化；失败前已经建出的表也不能未经确认就清除。

### 6.2 让网页和计划任务使用同一份密码

初始化为 MySQL 生成的 `config/local.php` 末尾通常包含：

```php
$config['db_dsn'] = getenv('DORM_DB_DSN') ?: $config['db_dsn'];
$config['db_user'] = getenv('DORM_DB_USER') ?: $config['db_user'];
$config['db_password'] = getenv('DORM_DB_PASSWORD') ?: '';
return $config;
```

使用宝塔文件编辑器，**仅将其中 `db_password` 那一行替换为**：

```php
$config['db_password'] = require __DIR__ . '/db-password.php';
```

保留其他已生成配置，尤其不要改动或重新生成 `app_key`。末尾应成为：

```php
$config['db_dsn'] = getenv('DORM_DB_DSN') ?: $config['db_dsn'];
$config['db_user'] = getenv('DORM_DB_USER') ?: $config['db_user'];
$config['db_password'] = require __DIR__ . '/db-password.php';
return $config;
```

**这一步不能省略。** 否则关闭终端后，FPM 和宝塔计划任务可能无法取得密码。

检查并收紧权限；初始化时由 root 创建的运行文件要交给网站用户：

```bash
/www/server/php/85/bin/php -l /www/wwwroot/dorm.example.com/config/local.php

chown root:www /www/wwwroot/dorm.example.com/config/local.php
chmod 640 /www/wwwroot/dorm.example.com/config/local.php

chown -R www:www /www/wwwroot/dorm.example.com/storage
find /www/wwwroot/dorm.example.com/storage -type d -exec chmod 700 {} +
find /www/wwwroot/dorm.example.com/storage -type f -exec chmod 600 {} +

unset DORM_DB_PASSWORD DORM_DB_DSN DORM_DB_USER
```

然后以网站用户运行检查，验证“不依赖刚才终端环境”也能连接：

```bash
runuser -u www -- /www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php /www/wwwroot/dorm.example.com/bin/console.php doctor
```

要求输出 `"ok":true`，没有未解决失败项，MySQL 表检查为 InnoDB。`doctor` 只是 CLI 检查，仍不能代替网页、HTTPS 或恢复演练。

如果以后改数据库密码，应同步修改 `db-password.php`，再分别检查 CLI 和网页。升级时要保留这个私有文件以及对 `local.php` 的上述引用。

## 七、配置宝塔 Nginx、HTTPS 与目录限制

### 7.1 先确认 FPM socket

宝塔常见配置引用是：

```nginx
include enable-php-85.conf;
```

对应全局文件常见位于：

```text
/www/server/nginx/conf/enable-php-85.conf
```

在宝塔文件管理器中查看该文件的 `fastcgi_pass`，或在 PHP 的 FPM 配置中查看 `listen`。本文示例假定确实为：

```nginx
fastcgi_pass unix:/tmp/php-cgi-85.sock;
```

如实际是另一个 socket 或 `127.0.0.1:某端口`，使用实际值。**只查看这个全局文件，不修改它，避免影响其他站点。** FPM 不应监听公网地址。

### 7.2 仅允许 API 入口执行 PHP

进入 **网站 → 该站点 → 设置 → 配置文件**，先另存当前配置的备份到公开目录之外。

确认当前 `server { ... }` 的 `root`、`index` 如第三节所示。然后：

1. 在**这个站点**中移除或注释通用 `include enable-php-85.conf;`，不再允许任意 `.php` 文件执行。
2. 清空本项目的通用 CMS／框架伪静态规则。本项目前端用 hash 导航，不需要把所有请求转给 `index.php`，也不使用 PHP 内置服务器的 `router.php`。
3. 若已有 `location /`，按下面内容修改原块，不要保留两个相同的块。
4. 保留宝塔的域名、日志、证书、ACME 验证和必要防护配置，不要整份盲目覆盖。
5. 在对应 `server { ... }` 内加入以下内容；若相同指令／location 已存在，合并或替换，不要重复。

```nginx
client_max_body_size 3m;
autoindex off;

add_header X-Content-Type-Options nosniff always;
add_header Referrer-Policy no-referrer always;
add_header X-Frame-Options DENY always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
add_header Content-Security-Policy "default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'" always;

location / {
    try_files $uri $uri/ =404;
}

# 唯一允许执行的 PHP 入口。
location = /api/index.php {
    try_files $uri =404;
    # 保留 PHP 返回的 JSON 错误，不继承上层 FastCGI 错误页拦截。
    fastcgi_intercept_errors off;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root/api/index.php;
    fastcgi_param HTTPS $https if_not_empty;
    # 固定的站点级参数；\n 分隔各 PHP 配置项。
    fastcgi_param PHP_ADMIN_VALUE "open_basedir=/www/wwwroot/dorm.example.com/:/tmp/\nsession.upload_progress.enabled=0\nsession.serialize_handler=php\ndisplay_errors=0\ndisplay_startup_errors=0\nlog_errors=1\nallow_url_include=0\npost_max_size=3M\nupload_max_filesize=2M";
    fastcgi_pass unix:/tmp/php-cgi-85.sock;
    fastcgi_read_timeout 30s;
}

# 其他 PHP 文件及 PATH_INFO 形式一律不开放。
location ~* \.php(?:/|$) {
    return 404;
}

# 隐藏文件不开放，但不覆盖宝塔的证书验证目录配置。
location ~ /\.(?!well-known(?:/|$)) {
    return 404;
}
```

这里 `HTTPS` 使用 Nginx 的实际 `$https`，不要在允许 HTTP 的入口里无条件写成 `on` 来假装启用了 HTTPS。

注意：

- `PHP_ADMIN_VALUE` 中的项目路径也必须替换；同一入口只保留一份合并后的参数，不要一行一项重复发送同名 FastCGI 参数。示例里的 `\n` 是配置项之间的换行分隔。
- 参数值必须是维护人员配置的固定文本，不得用 `$http_*` 等用户可控请求头拼接 PHP 设置。FPM 不对公网开放。
- 本片段只放在本项目站点中，不修改全局 `nginx.conf`、其他站点配置或 `enable-php-85.conf`。Nginx 仍是共享服务，修改前留备份、检测通过后平滑 reload，不要 stop／restart 来试错。
- `fastcgi_pass` 必须与实际 PHP 版本一致。
- 如果配置中已有更早的通用 PHP 正则处理器，应移除该通用处理器；否则可能绕开“其他 PHP 返回 404”的规则。
- SSL 开启后若面板拆成多个 `server`，核对真正提供 HTTPS 的块也包含这些设置，并保证 HTTP 只跳转或处理证书挑战。
- 保存前执行面板配置检测；如使用终端，宝塔常见检测命令为 `/www/server/nginx/sbin/nginx -t`。通过后才重载。
- 后续在面板切换 PHP 版本可能重新插入通用 PHP include，要重新检查站点配置及 socket。

### 7.3 核对宝塔防跨站设置（open_basedir）

本项目入口在 `public/`，但必须读取上一级的 `src/`、`config/` 并写入 `storage/`。因此允许目录应是：

```text
/www/wwwroot/dorm.example.com/:/tmp/
```

不能只允许：

```text
/www/wwwroot/dorm.example.com/public/:/tmp/
```

上面的 API location 已给出**仅对这个入口生效**的 `PHP_ADMIN_VALUE`。还需核对站点已有 `.user.ini`／FPM 池设置没有施加更窄的限制。若报 `open_basedir restriction in effect`，通过面板的站点防跨站配置／受控配置管理把本项目允许范围改为项目目录。只改 Nginx 参数时检测并平滑 reload Nginx；`.user.ini` 有读取缓存，应按实际缓存周期等待并复验。若必须改池配置，不要自行重启共享 PHP，应先安排维护或使用独立实例。

不要一遇到错误就关闭所有网站的防跨站，也不要把允许路径扩展成整台服务器。`.user.ini` 可能被面板加锁，应按面板支持的方式维护，不要盲目执行 `chattr -i` 或删除安全文件。

### 7.4 申请 SSL 并强制 HTTPS

在 **网站 → 设置 → SSL** 中：

1. 核对域名已解析到服务器；存在 AAAA 记录时，IPv6 也必须指向正确服务器，否则删除错误的记录。
2. 启动站点，确认上述公开根目录和访问限制已保存。
3. 通过宝塔申请受信任证书，或安装你已有的有效证书；保持面板的 ACME 验证规则可用。
4. 开启 SSL，使用 TLS 1.2／1.3。
5. 开启强制 HTTPS，实际检查 `http://域名/` 跳转到 `https://域名/`。
6. 检查自动续签任务及后续续期结果，不要只看申请当天成功。

初次使用建议让 Nginx 直接处理 HTTPS，不叠加 CDN／反向代理。若今后加代理，需要另外核对信任边界、真实 HTTPS 识别及精确同源配置，不能简单信任任意请求头。

实际访问必须与 `config/local.php` 的 `app_url` 完全同源，包括协议、主机和非默认端口。不要用 IP、另一个别名或 `www` 域名去登录，却仍保留旧的 `app_url`。

**正式环境不要执行 `demo`，不要使用虚构账号或演示密码。** 名册导入和登录账号创建是不同操作，导入 CSV 不等于已创建所有寝室长登录账号。

### 8.2 检查真实 API

访问以下地址，应返回 JSON，而不是 PHP 源码、空白页面或 502：

```text
https://dorm.example.com/api/index.php?action=session
```

未登录时正常结果类似：

```json
{
  "ok": true,
  "data": {
    "user": null
  },
  "csrf": "服务端生成的值"
}
```

实际响应还有其他配置和时间字段，不要求与示意完全相同。也可执行 GET 查看状态和响应头：

```bash
curl -i 'https://dorm.example.com/api/index.php?action=session'
```

这只验证匿名接口、HTTPS 和基础配置，不代表密码登录或管理业务已经验收通过。

### 8.3 完成管理员真实认证

打开 `https://dorm.example.com/`：

1. 进入“首次激活”，输入真实学号及一次性激活码。
2. 设置 15–64 个字符的独立长密码，避免包含学号或简单重复。
3. 使用该密码实际登录。
4. 按页面引导绑定验证器，输入动态码完成绑定。
5. 将一次性恢复码存入私有密码管理器或其他受控位置。
6. 退出，再用密码＋新的动态码重新登录，确认真实链路可用。

验证器并不依赖短信服务；应保持手机和服务器时间同步。未绑定 TOTP 的管理员不能进入管理业务，这不是部署故障。

正式名单导入、寝室长／班委账号建立、寝室授权和请假安排按[使用手册](使用手册.md)进行。默认北京时间 **22:30 开放、22:35 初报截止**；若要在别的时点演练，应使用独立测试实例，不要为测试正式库而来回修改规则或注入时间。

## 九、添加宝塔每分钟计划任务（必须）

网页轮询不能替代调度。无人打开网页时，也需要服务器建立任务、冻结名册、生成首报及记录调度状态。

宝塔：**计划任务 → 添加任务**：

- 类型：Shell 脚本
- 名称：`归寝-每分钟调度`
- 周期：每分钟一次（对应 cron `* * * * *`）
- 脚本内容如下

如果宝塔提供“执行用户”，可直接选择真实 FPM 用户 `www`，脚本只写：

```bash
#!/bin/bash
unset DORM_CONFIG DORM_DB_DSN DORM_DB_USER DORM_DB_PASSWORD
exec /www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php /www/wwwroot/dorm.example.com/bin/console.php tick
```

**如果该 Shell 任务固定由 root 执行**，使用下面版本，不要和上面的版本同时建立两个任务：

```bash
#!/bin/bash
unset DORM_CONFIG DORM_DB_DSN DORM_DB_USER DORM_DB_PASSWORD
exec runuser -u www -- /www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php /www/wwwroot/dorm.example.com/bin/console.php tick
```

不需要在计划任务里写数据库密码；第六节完成后，CLI 也会读取同一份私有密码文件。不要依赖面板默认 `php` 命令，必须用对应版本完整路径。

保存后点“执行一次”，查看返回状态和任务日志，再进入网站设置／运行信息核对最近成功调度时间。可先在终端验证相同身份下的命令：

```bash
runuser -u www -- /www/server/php/85/bin/php -d session.upload_progress.enabled=0 -d session.serialize_handler=php /www/wwwroot/dorm.example.com/bin/console.php tick
```

任务配置完成不等于已经执行成功：至少等待两个实际周期并检查成功时间持续更新。核对服务器时钟及时间同步；业务时区固定为 Asia/Shanghai，不要求为本项目强行修改整台服务器的时区。

计划任务日志、面板日志也属于私有运维资料，设置日志保留／轮转，避免无限增长。若返回 `catchup_pending`，表示还有待补跑日期，应继续由后续调度处理并观察，不要手工伪造旧的生成时点。

## 十、备份、恢复与更新注意事项

### 10.1 先建立宝塔备份任务

至少设置：

1. **数据库备份**：每天备份本项目专用库。
2. **应用配置／程序备份**：保存项目源码及私有 `config/local.php`、`config/db-password.php` 和必要运行资料。
3. **异机保存**：不能只存服务器本机；按学校或班级的数据规则，使用经过确认的私有备份目的地，限制访问并加密。

配置里有应用加密密钥 `app_key`。只有数据库、丢失原 `app_key`，不能完整解密既有验证器数据。数据库密码文件和站点配置也要受控保存。不要把备份放在 `public/`，不要通过公开网盘或聊天群分享。

宝塔“数据库备份”与项目的加密 `.dcb` 是两种不同机制。**面板备份不能默认认为已加密，也不能默认包含应用配置。** 保留周期、异机目标和恢复责任人需要明确设置。

### 10.2 如使用项目内置加密备份

另见[通用部署教程的备份与恢复章节](部署教程.md#5-备份与恢复)。宝塔环境需要额外核对：

- CLI `proc_open`／`proc_close` 可用；宝塔常把它们放在禁用函数列表中。仅为受控 CLI 备份／恢复提供所需能力，不要直接清空整份 Web 禁用函数列表。
- `mysqldump`、`mysql` 与服务器版本兼容，宝塔常见目录为 `/www/server/mysql/bin/`。
- 内置程序按命令名查找这些工具。可在**备份／恢复 CLI 任务**的环境中设置 `PATH=/www/server/mysql/bin:/usr/bin:/bin`，无需修改全系统 PATH 或 FPM 配置。
- `DORM_BACKUP_KEY` 是独立的 32 字节随机值的 base64，只给受控备份／恢复进程使用，不写进 Nginx 或共享 FPM 池，不随 `.dcb` 文件一同公开保存。
- 配置文件采用本文的私有密码引用方式后，日常 CLI 不再需要 `DORM_DB_PASSWORD`；不要把通用教程中的 `/etc/dorm-check/` 示例路径和本文路径不加区分地混用。
- 维护、恢复进程的身份及生成文件权限必须保证 FPM 用户能正确读取维护标记；优先按 FPM 用户执行应用维护命令，并为它单独提供必要的备份读写权限。

### 10.3 恢复不是直接在正式库“试一下”

先在隔离库演练。项目内置恢复会撤销旧密码、会话、一次性码、TOTP、恢复码及旧授权，恢复后必须核实人员、重发凭据、重绑验证器和重新授权。恢复中的全阻断标记不能直接删除来强行开放。

**宝塔直接导入 SQL 不会自动执行上述应用恢复保护。** 因此不能把“面板导入数据库成功”当成应用已经安全恢复。必须同时核对配置密钥、运行状态、会话失效和授权，由维护人员制定并验证完整流程。

### 10.4 更新程序

- 更新前保存可恢复备份，核对目标路径；需要暂停业务时以网站用户执行 `maintenance:on`。
- 不覆盖 `config/local.php`、`config/db-password.php`、`storage/`，也不要重新执行 `init`。
- 如新版需要迁移，按该版本说明临时授予权限并执行 `migrate`；不要默认每次上传都必须迁移。
- 核对 OPcache 的代码更新策略，确认网站实际运行新代码。独立 PHP 实例可仅重载自身；共享实例不要无计划重启或全局清空缓存。需要缓存失效时由维护人员采用受控的项目级处理方式；若只能重载共享实例，须安排所有受影响站点的维护窗口。不要公开临时 `opcache_reset()` 接口。
- 再检查 Nginx 是否被面板重写了 PHP 规则；检查 `doctor`、真实登录、导出和计划任务。
- 核实后以网站用户执行 `maintenance:off --confirm=REVIEWED`；至少须有一名有效且已绑定验证器的管理员。不要仅凭首页能打开就解除维护。

### 收紧日常数据库权限

宝塔新建账号可能默认拥有该库的全部权限；**面板创建成功不等于已经最小化授权**。初始化完成后，维护人员先在管理会话用 `SHOW GRANTS` 查看实际授权，再将日常账号收紧为该库必要的数据操作权限，例如：

```sql
SHOW GRANTS FOR 'dorm_app'@'127.0.0.1';

REVOKE ALL PRIVILEGES
ON dorm_check.* FROM 'dorm_app'@'127.0.0.1';

GRANT SELECT, INSERT, UPDATE, DELETE
ON dorm_check.* TO 'dorm_app'@'127.0.0.1';
```

示例仅针对这个数据库和这个来源账号，必须在有管理权限的会话中执行，不是让网站账号自己执行。若实际用户／来源不同，先核对再修改；也要确认它本来没有全局权限。`REVOKE ALL PRIVILEGES ON 库.*` 不负责清除所有层级的授权转授能力；若 `SHOW GRANTS` 显示该库还带 `WITH GRANT OPTION`，应另外由管理员执行 `REVOKE GRANT OPTION ON dorm_check.* FROM 'dorm_app'@'127.0.0.1';`，再检查授权结果。

收紧后重新执行 `doctor`、网页读写和调度。以后迁移建表、`mysqldump` 或恢复所需权限可能不同，应为受控维护窗口／维护账号单独配置，不能长期给普通网站账号 root、全局权限或 DROP 权限，也不能认为只授四项数据权限便已验证备份可用。

## 十二、常见故障速查

| 现象 | 优先检查 |
| --- | --- |
| 首页 403 或显示宝塔默认页 | 项目是否多套一层目录；运行目录是否 `/public`；默认文档是否 `index.html`；是否访问了正确域名 |
| API 下载成 PHP 文件／源码显示 | Nginx API 精确 location 是否生效；站点是否仍是静态配置。应立即停止站点修复，不要继续输入凭据 |
| API 404 | 是否误把请求重写给 `index.php`；精确 location 是否在实际 HTTPS server 内；`root` 是否正确 |
| 502 Bad Gateway | 对应 PHP-FPM 是否启动；socket／端口是否与实际版本一致；Nginx 是否有访问 socket 的权限 |
| 提示系统尚未初始化 | 是否成功生成 `config/local.php`；路径、读取权限是否正确；是否有其他 `DORM_CONFIG` 干扰 |
| 初始化提示数据库非空／配置存在 | 确认是否已经部署或上次部分完成，不要直接删库重来 |
| MySQL 1064，位置在 `delayed INTEGER` 附近 | 上传修复后的 `src/Schema.php`、`src/Domain.php`；这是保留字转义问题，失败后的补齐步骤见 [MySQL 初始化错误修复](MySQL初始化错误修复.md)，不要为此改全局配置或反复删库 |
| CLI 能连数据库，网页连不上 | 是否完成第六节的 `db_password` 引用修改；密码文件权限；FPM open_basedir；网页实际 `pdo_mysql` |
| MySQL `Access denied` | 用户、密码、端口和授权来源是否匹配 TCP `127.0.0.1`；不要临时开所有 IP |
| `open_basedir restriction in effect` | 允许的是项目目录还是仅 `public/`；站点 `.user.ini` 或 FPM 池有无更窄限制 |
| `UNSAFE_RUNTIME` | 检查实际 FPM 补丁版本，不是只看终端默认 `php` 或面板的大版本名 |
| `UNSAFE_CONFIGURATION` | 检查本项目 API location 的 `PHP_ADMIN_VALUE` 是否正确传入 `session.upload_progress.enabled=0`，再核对实际请求；CLI 则使用教程中的 `-d` 参数。不要因此修改共享 php.ini 或重启全部 worker |
| `HTTPS_REQUIRED` | 是否真的通过 HTTPS；FastCGI 是否传递实际 `$https`；是否混入未经配置的反向代理 |
| 403 请求来源不正确 | `app_url` 与浏览器的协议、域名、端口是否一致，是否换了别名／IP |
| 登录后立刻退出 | Cookie、HTTPS、服务器时钟、账号状态，以及 `storage/sessions` 的运行用户权限 |
| 管理员登录后要求绑定验证器 | 正常安全要求，按页面绑定 TOTP 后再访问业务 |
| 动态码一直错误 | 手机和服务器是否同步时间；是否使用了该账号对应的新验证器条目 |
| 导出报错 | FPM 的 zip、xmlwriter、`storage/exports` 权限、近期验证和当前角色权限 |
| 没有自动生成当晚任务／日报 | 是否创建了每分钟 `tick`；计划任务用户、PHP 路径、退出码、后台最近成功时间 |
| 计划任务提示找不到 php | 使用 `/www/server/php/实际版本/bin/php` 完整路径，不依赖默认 PATH |
| 内置 MySQL 备份失败 | CLI 禁用函数、mysqldump PATH、工具兼容性、维护权限及输出目录；不要把密码加进命令参数 |

查错时查看宝塔网站错误日志、对应 PHP-FPM 日志和计划任务日志。应用内部错误会带错误编号；只提供必要的去敏错误信息，不公开数据库密码、`app_key`、激活码、恢复码或整班名单。
