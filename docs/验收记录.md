### 浏览器认证证据的限制

浏览器用 `work/php-wasm/fixtures.php` 在隔离虚拟文件系统建立的**预认证虚构 Session**。该文件不在应用 `public/` 中，真实程序没有测试登录接口。它只用于驱动授权后的业务页面，不证明密码正确验证、真实激活成功或浏览器中的管理验证器绑定成功。

管理账号 TOTP 绑定、RFC 6238 测试向量、重放限制、恢复码哈希／单次使用及旧会话撤销，另由直接 PHP 测试验证；不能据此补称整个 Argon2id 登录链通过。

浏览器虚构环境通过普通配置把查寝时间设为 00:00，方便在当天实际服务器时钟下操作；因此截图出现“每天 00:00”。这不是正式默认时间变更，也没有把任意测试时间暴露给 HTTP。实际应用默认仍是 22:30／22:35。

## 3. 已覆盖的重要行为

### 业务与时间

- 读接口不建任务、不冻结、不保存日报、不更新写锁。
- 查寝前不能正式提交；没有 cron 时正式提交仍会核对开放时间和必要冻结。
- 整寝初报完整、无重复、无越权成员；任一成员失败整批回滚。
- 原始初报、更正值、当前状态，以及初报／当前去向分别保存。
- 初报图书馆外出、当前已返寝不会把图书馆错误保留为当前去向；当前仍外出或待核实时必须填写当前已知情况。
- 同请求幂等重试、同键不同内容拒绝、陈旧版本冲突；没有静默覆盖。
- 跨零点补报属于原晚，人工发生时间与服务端接收时间分别保留。
- 请假必须由后台核实，联系“确认安全”不自动改成在寝；撤销例外转待核实。
- 旧晚任务须当前授权，交接必须明确指定完整任务。
- 全部房间结项及重开会同步夜任务状态；空范围不留下虚假缺报。
- 无人报也生成完整首报，延迟补跑使用实际时点，自动日报不重复。

### 名册和权限

- CSV 前导零、重复学号、缺负责人、班级不符、预览内容变更等校验。
- 导入只新增／更新，不自动删除未出现人员；显式移出只影响后续范围。
- 冻结名册不随当前住宿导入被覆盖；调整必须带理由和版本。
- 转寝保留原始申报；个人跨寝历史可追溯，不泄露原寝其他人的记录。
- 当前数据库角色、账号状态与授权有效期每次核对；撤权立即阻断旧会话及缓存重试。
- 页面退出／失效清理私有状态，轮询不无限续期；恢复码单次使用。

### 报表和运维

- 固定日报不可变，明细与事件取同一快照；六工作表总口径一致。
- 文本单元格不写成公式，学号与房号保留字符串。
- 私有导出流式下载，备份认证篡改拒绝，恢复撤销旧身份凭据和授权。
- 保留清理须 CLI 明确确认，不把设置天数误当自动删除开关。
- 计划任务运行信息、审计详情及分页可查看。

“两个报告者冲突”是旧版本顺序提交的验证，**没有实际进行多进程 MySQL 并发压测**。

## 6. 复现方式

### 有原生 PHP 时（优先）

在支持所需扩展及 Argon2id 的隔离环境，从 `outputs/dorm-check/` 运行：

```text
php tests/run.php
node --check public/assets/app.js
```

PHP 测试自行建立内存 SQLite，不加载运行配置。缺少 Argon2id 时会明确跳过成功密码链；具备算法时会运行额外密码链测试，测试总数相应增加。

另按部署教程建立**隔离 development 实例**并启动本地服务，再运行：

```text
node tests/http.mjs http://127.0.0.1:8765
```

设置进程环境变量 `DORM_TEST_REPORT` 为已有目录下的目标 JSON 路径，可保存 HTTP 测试结果。不要对正式服务运行验收写操作。

### 本轮已有 WASM 替代环境

从工作区根目录：

```text
node work/php-wasm/check.mjs lint
node work/php-wasm/check.mjs test
node work/php-wasm/serve.mjs --fixtures
```

服务打印当前私有 `ui-fixtures-<PID>.json` 路径；在另一个终端立即运行：

```text
node work/php-wasm/browser-smoke.mjs work/php-wasm/ui-fixtures-实际PID.json
```

fixture 中管理账号近期验证窗口为五分钟，不能使用很早以前的元数据重复跑。每次完整浏览器回归应先停止旧服务，再用全新虚构库启动；不要同时占用同一端口。`check.mjs` 同样支持 `DORM_TEST_REPORT` 保存 JSON。

WASM 适配器依赖当前 `work/php-wasm/` 中已有的本地包，它是验收工具而非生产程序依赖；独立分发 `outputs/dorm-check/` 后优先用原生 PHP。建议后续用 `/run-skill-generator` 把已经验证的本地启动流程固化为项目技能。不要将本地适配器或私有会话元数据上传、部署到网站。
